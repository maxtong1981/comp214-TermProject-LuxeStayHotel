# Final Submission Guide

Keep final release files here. Maintain working code in `database/` and `website/`, then prepare submission copies after verification.

## Required filenames

Replace `GroupName` and `ProjectName` with the group's confirmed names. Do not use spaces or `#` in filenames. The group notes use LuxeStay as the project name; the group name is still to be confirmed.

| Deliverable | Filename pattern |
|---|---|
| Schema and objects | `GroupName_ProjectName_TermProject_Schema.sql` |
| Demonstration script | `GroupName_ProjectName_TermProject_Demo.sql` |
| Report | `GroupName_ProjectName_TermProject_Report.docx` or `.pdf` |
| Front-end source archive for bonus | `GroupName_ProjectName_TermProject_FrontEnd.zip` |

The brief permits Word or PDF for the report; its filename example uses `.docx`. Confirm any additional LMS restrictions. The interface marking wording should be clarified with the instructor as recorded in the requirements checklist.

## Report section checklist

Members write their own assessed report material. Assemble it in this order from section 7:

1. Title page: project name, group name, course and section, submission date.
2. Members: full names and student IDs.
3. Contribution statement: actual objects, interface parts, and demonstrations completed by each member.
4. Problem domain: one or two paragraphs.
5. ER diagram: all tables, keys, and relationships, legible at full page size.
6. Front-end wireframe.
7. Table purposes and constraints.
8. Programming unit descriptions: purposes, handled exceptions, and callers.
9. Execution evidence in section 4 order, with screenshots, captions, and selectable output text.
10. Front-end screenshots and short explanations.

Also include the contribution initials and signed original-work declaration required by the final checklist.
